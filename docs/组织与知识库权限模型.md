# 组织与知识库权限模型

## 1. 数据边界

系统使用飞书 `tenant_key` 作为组织隔离边界，不用用户名、邮箱域名或前端传参判断组织。

- 个人知识库：仅所有者可读写；管理员也不能读取。
- 组织知识库：同一 `tenant_key` 的成员可检索和只读查看；Owner、管理员可新增、更新、删除和重建索引。
- 飞书文档与聊天：继续使用当前用户的 `user_access_token` 实时检索，权限以飞书返回结果为准，不复制成组织离线索引。
- 跨组织公开知识：当前不默认开放。以后如实现，必须是独立的“发布”流程，包含内容审核、敏感信息检查、撤回和审计，不能把组织知识库直接改成公开。

## 2. 首次接入与管理员

每个租户有且只有一个 Owner。

1. 新组织没有迁移配置时，同租户首位成功登录者成为 Owner。
2. 已有生产部署可在 `ADMIN_OPEN_IDS` 配置一次性引导名单：第一位成为 Owner，其余成为管理员，避免普通用户抢占已有组织。
3. 后续同租户用户首次登录后自动成为 Member，并出现在右上角“组织管理”。
4. Owner 可以把 Member 提升为管理员、撤销管理员，或把 Owner 转移给另一名已登录成员。
5. 当前 Owner 不能直接降级；必须先转移 Owner，因此系统始终保留一个可管理主体。

系统不要求读取完整飞书通讯录。成员列表只包含已经登录过本系统的同租户用户，减少权限申请和隐私暴露。

## 3. 角色权限

| 能力 | Owner | 管理员 | Member |
| --- | --- | --- | --- |
| 使用组织知识库检索 | 是 | 是 | 是 |
| 维护组织知识库 | 是 | 是 | 否 |
| 查看组织质量案例/聚合看板 | 是 | 是 | 否 |
| 修改成员角色/转移 Owner | 是 | 否 | 否 |
| 读取他人个人知识库 | 否 | 否 | 否 |
| 修改他人模型/开发者设置 | 否 | 否 | 否 |

右上角“模型配置”和“开发者设置”始终写入当前用户会话，只影响本人。组织级参数若以后增加，必须放在“组织管理”中，使用独立接口和审计记录，不能复用个人设置接口。

## 4. 检索与索引

用户提问时：

1. 个人上传库和本组织上传库分别执行 BM25 + 向量检索。
2. 两个权限域的候选合并后，进入统一的内容读取、相关性法官和证据选择。
3. 飞书文档与聊天仍走实时搜索；不会因为组织库索引而绕过飞书权限。
4. 组织上传库和个人上传库使用不同的物理存储键，不依赖查询过滤做“软隔离”。

## 5. 迁移与故障关闭

- OAuth 返回 `tenant_key` 时始终使用真实值。
- 老会话无 `tenant_key` 时，单租户部署应显式配置 `FEISHU_TENANT_KEY`。
- 若既没有真实 tenant key 也没有部署配置，本地开发才退化到应用级命名空间；多租户生产不得依赖这一兜底。
- 角色校验在服务端完成。隐藏按钮只是交互优化，不是权限边界；越权写组织库返回 HTTP 403。
