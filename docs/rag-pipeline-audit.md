# RAG 检索链路逐环质量审计

目标：对外可售的知识问答，每一环都做到业界最佳，最终质量才不会差。
标注：✅已做好 / 🟡有但naive / ❌缺失 / 🔧本轮在做

| # | 环节 | 现状 | 业界最佳实践 | 差距 / 计划 |
|---|---|---|---|---|
| 1 | **查询理解** Query understanding | 🟡 关键词提取；无多轮改写 | 意图识别、**多轮指代消解**（"它呢?"结合上下文改写）、拼写纠错、复杂问题分解 | 加"带历史的问题改写"；复杂问分解 |
| 2 | **查询扩展** Query expansion | 🔧 多查询已实测(10→21)，待接线 | **多查询**（同义/上位/实体）、**HyDE**（假设答案再向量召回） | 接线多查询；评估 HyDE |
| 3 | **召回** Recall | 🟡 飞书关键词单路；上传库=关键词 | **Hybrid**（BM25+向量，RRF融合）、over-fetch（召回50-100再精排） | 飞书文档受限只能关键词→多查询缓解；**上传库必须做向量召回** |
| 4 | **切片** Chunking | 🟡 定长500字滑窗，断句 | **结构感知**：按标题/段落/表格/**Q&A对**切；保留 section 路径元数据；**small-to-big**（召回小块、喂大块上下文）；绝不切碎句子/表格 | ❗重点改：结构感知切片 + 每块带标题/层级元数据 |
| 5 | **向量** Embedding | 🟡 智谱embedding-3(2048d)，批量；**每次查询重算** | 强模型；**缓存/持久化**（同内容不重复embed）；query/doc 非对称指令 | ❗加缓存（省延迟省钱、为索引铺路） |
| 6 | **索引** Index | ❌ 飞书=查询时算；上传库无向量索引 | 向量索引(HNSW/IVF)、元数据过滤；小规模可用扁平余弦但要**持久化** | 上传库建持久化向量索引 |
| 7 | **排序** Ranking/Rerank | 🟡 向量余弦排序 | 两段式：bi-encoder召回→**cross-encoder重排**(BGE/Cohere/Jina)；或 **LLM listwise**(RankGPT)；**RRF**融合多信号 | 加 RRF(词法+向量)；cross-encoder 做可插拔 |
| 8 | **相关性过滤** Filtering | ✅ **LLM法官(0~3)**已实测能判噪音为0 | 校准化阈值（LLM判分即校准）、**去重**近似块、**MMR**多样性 | 补去重/MMR；法官已是强项 |
| 9 | **上下文组装** Context assembly | 🟡 按序拼命中段 | 按相关度排、去重、**"lost in the middle"**（最相关放首尾）、**small-to-big**扩上下文、带来源元数据 | 加 small-to-big、去重、首尾摆放 |
| 10 | **生成** Generation | ✅ 接地prompt、引用、信息不足如实说 | 忠实性约束、拒答 | 基本达标 |
| 11 | **溯源** Citation/Anchor | 🟡 行内[n]✅；**深链锚点=关键词粗匹配(会定位错段)** | 精确定位到命中块；**归因校验**（每句话是否真被引用段支撑） | ❗修锚点→锚到法官命中的真实段；评估归因校验 |
| 12 | **评估闭环** Eval/Feedback | ❌ 无，全靠人工眼看 | **离线评测集**（query+期望文档，测 recall@k/MRR/忠实度）、👍👎反馈、线上日志回流 | ❗建评测集——让调参用数字说话，不靠感觉 |

## 优先级（我的独立建议，按"投入产出比 × 依赖关系"）

- #12 评测集（没有它，后面每一步改动都无法量化验证——这对你"大量测试"是刚需）
